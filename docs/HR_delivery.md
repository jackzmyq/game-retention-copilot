# 面向 HR 的交付说明

## 推荐的交付顺序

1. **优先附件：两页 PDF 项目介绍。** 对方无需安装环境即可了解业务问题、结果、分析能力、适用范围和使用方式。
2. **可选：免安装浏览包。** 解压 HR_review_pack.zip 后，打开 PDF 或 index.html；内含中英文介绍及决策简报。
3. **技术深入：单独的源码包或实际已发布的仓库链接。** 不将源码安装设为 HR 阅读前提。源码：https://github.com/jackzmyq/game-retention-copilot 。访客版：https://jackzmyq.github.io/game-retention-copilot/ 。

这些文件由 setup.ps1 生成；也可运行 `python scripts/build_hr_pack.py` 重建介绍包和 PDF。生成内容与当前校验通过的分析结果同源。

## 应如何定位作品

“游戏留存实验分析与 AI 运营助手”：一个业务问题明确、可运行、可复现的个人分析作品。能够迁移的是指标、实验评估、质量检查和交付流程；当前程序仅适配这份固定的 Cookie Cats 数据，不是支持任意游戏的通用平台。

方法可迁移至新手引导、内容解锁、版本或功能实验，但需要重新获取数据、定义指标、核验实验并验证结论。双语汇报已实现，真实地区分析未实现；没有将语言能力等同于地区测量。

## 首次浏览路径

交互版默认进入“作品导览”，提供三分钟路线和跳转按钮。无需 Key 的体验是：实验决策 → 决策沙盘 → 行为与质量 → 离线助手。讲解 AI 时应明确区分固定规则与真实模型调用，后者尚待配置验收。

## 外部访问的实际条件

127.0.0.1 / localhost 只能访问查看者自己的电脑，不能作为发给 HR 的线上地址。介绍包可离线阅读；HR 可通过 GitHub Pages 访客版操作分析、沙盘、下载及离线规则；完整 Python/SQL 与可选模型接口保留在源码中。不要在简历中填写当前本地地址作为公开演示。

PDF/HTML 是介绍阅读版，不会在文档内执行数据库或模型。实际交互、SQL 与真实模型使用说明属于应用或源码文档。

## 提交前核对

- 使用与真实验收状态一致的简历描述。
- 对外说明“个人项目，开发使用 AI 编程辅助”，不虚构独立手写全部代码或已上线成效。
- 作品介绍、源数据口径、界面和简历中的数值一致。
- 不提交 .env、虚拟环境、原始数据或私人对话轨迹。
- 发送前确认仓库及访客版地址可访问。
