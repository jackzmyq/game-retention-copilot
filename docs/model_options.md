# 模型连接是否必须

## 当前选择

当前架构把计算和模型连接分开。SQL、统计、情景、图表、双语简报和证据工作台在本机执行；没有 API Key 也能使用。只有让模型理解自由文本、结合上下文自主选择工具并组织回答时，才需要启用 LLM。

当前已经实现两种模式：DeepSeek 云端 API 和明确标注的离线固定规则。没有宣称本地模型已部署。

| 方案 | 适合本次项目的地方 | 需要承担的成本 |
|---|---|---|
| 云端 API（当前 DeepSeek 适配） | 快速验证真实工具调用，独立演示完整 LLM 流程 | 密钥、网络、调用费、聚合证据的外发 |
| 本地模型（未来可适配） | 可在本机处理问题和证据 | 先检查硬件，再部署模型、验证工具调用质量与延迟；当前未实施 |
| 离线规则（当前已实现） | 稳定展示查询和证据，不依赖模型服务 | 固定意图能力，不具备通用多轮理解，不等同 LLM Agent |

对“快速构建可演示的分析工具链”，云端 API 是当前部署工作较少的方案，而不是普遍最优解。选择本地模型需基于实际硬件和验证结果；选择纯规则则应将项目如实表述为分析自动化，不把它包装成大模型实践。

接入 API 本身不构成项目亮点。可复核的指标、完整的分析、正确的业务判断、模型边界与真正完成的调用验收才是应展示的内容。不要编造模型准确率、节约时间或业务增益。

## 数据传递范围

实时模式向配置的 DeepSeek HTTPS 地址发送当前问题、最多六条先前对话、指标知识及工具返回的聚合证据。API Key 只用于请求认证，不进入回答和证据轨迹。聊天中不要输入凭据或其他私人信息。

目前尚未完成真实模型验收；配置后应按 verification.md 验证成功与失败案例。没有密钥时，核心项目和离线演示可继续使用。
